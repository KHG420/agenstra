# 接入 Agenstra 到宿主

在开发者的宿主仓库完成接入。使用当前 coding agent 自带的代码阅读、编辑、命令和测试能力；本 Skill 提供接入知识和验收要求。它是开发期指导，不是运行期能力包中的业务技能。

首要成果是可用的接入代码、经过核对的能力契约和可复现的本地验收。按开发者选择的范围推进；只有讨论或审计授权时，交付分析和方案。

## 确认宿主与框架依据

- 读取宿主项目指令，保留已有修改，确定构建、登录、权限和测试入口。使用项目要求的代码调查工具。
- 定位 Agenstra 源码或发行包，记录所用版本或 commit。阅读该版本的 `docs/quick-integration.md`、`docs/host-integration.md`；Web 接入再阅读 `docs/web-integration.md`，能力包读取 `docs/capability-management.md`。文档、SDK、服务及清单以目标版本为准。
- 官方源码是 `https://github.com/KHG420/agenstra`。若缺少本地源码，可在任务允许的范围内获取开发副本并记录 commit；不能确认版本、依赖或凭据时，继续宿主调查和不受阻的代码工作，说明受影响的验收。
- 框架接入保持公共边界：独立服务通过 HTTP 使用；Go 嵌入使用 `github.com/KHG420/agenstra/sdk/go`。应用业务规则由宿主实现，框架内核修改须有对应任务授权。

## 从原操作推导接入

追踪本次需要接入的操作，从页面/API 入口到真实业务函数、权限校验和结果查询。整理一份紧凑映射：原操作、能力名、函数或接口位置、执行主体、读写影响、审批要求、幂等保证和验收方法。按实际代码与契约填写，未知项保持明确未知。

选择最少必要路径：

| 宿主能力 | 接入路径 |
| --- | --- |
| 已有 REST/OpenAPI | 独立 Agenstra 服务 + 选定操作的 REST 能力包 |
| 已有 MCP | 发现并选择工具，固定完整契约后绑定 |
| 依赖当前页面状态、登录或本机下载的函数 | Web SDK + frontend profile + 原函数 handler |
| 后端业务与页面操作都需要 | 组合后端能力包与浏览器 integration，分别授权 |
| Go 原进程内调用 | 公开 Go SDK + CapabilityProvider |

默认 Web 宿主采用独立服务。纯浏览器模式可省略后端能力包；只有聊天需求时省略 browser/profile/handlers。已有可靠业务接口可直接复用，不为接入重复实现业务流程。缺少可调用接口的 GUI 接入应明确额外适配范围。

## 生成并完成绑定

Web 宿主和现有工具的使用方式见 [Web 宿主接线](references/web-host.md)，按选定路径阅读。

- 契约只暴露选定的操作。OpenAPI/MCP 导入所得是草稿，须根据原实现核对影响、权限、输入输出、失败语义、幂等、异步终态与业务成功证据。
- handler 调用原业务函数或原接口；生成的占位 handler 必须完成绑定。前后端凭据、身份和授权沿用可信服务端路径。
- 把失败、仅受理、成功和结果未知分别处理。超时或连接失败不能证明写入未执行；有不确定结果时核对原调用，不能换 ID 重放。
- 使用框架已有的审批、回执和恢复入口；按原宿主实现绑定生命周期、业务版本和必要的结果查询。适用的开发者授权继续有效，不逐步重复请求确认。

## 独立验收与修复

完成接线前读取 [本地验收](references/acceptance.md)。同时检查宿主原有行为、接入协议和代表性业务结果；coding agent 的完成声明、Schema 通过或一次模型回答都不能代替这些检查。

依据失败证据修复当前接入，保持检查器与有效断言；不通过关闭权限、伪造回执、改弱成功条件或跳过用例换取通过。真实模型验证按开发者的授权与可用凭据显式执行，和本地替身测试分别报告。

交付接入代码、能力与原实现映射、版本依据、可复现命令及实际结果。区分通过、失败和未执行；缺少凭据或运行条件时保留可继续验收的产物，说明最少缺失信息。按资源归属关闭本任务启动的服务和测试容器，结束本任务创建的浏览器测试会话；连接用户原浏览器时仅解除连接，保留原有资源。
