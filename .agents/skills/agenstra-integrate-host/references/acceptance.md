# 本地验收

围绕本次接入的操作选择用例，覆盖实际触发的身份、权限、写入和恢复路径。成功规则从原业务需求与权威查询中取得，不由模型的完成措辞推导。

## 宿主侧检查

| 范围 | 可核对证据 |
| --- | --- |
| 原有业务 | 原构建/相关测试通过；新 handler 调用原函数；原 UI/API 操作仍正常 |
| 登录换票 | 真实登录和 CSRF 校验生效，未登录/无效来源拒绝；浏览器只得到短期票据 |
| 用户和租户隔离 | 独立账号与对象验证跨主体访问被拒绝，原后端继续验证业务授权 |
| 能力绑定 | 选定动作能执行，新增动作有真实 handler，profile/handler 版本和服务端一致 |
| 写入与审批 | 精确参数审批、拒绝/撤销后不执行；按权威查询核对真实结果和副作用 |
| 重试与恢复 | 本次使用的稳定请求 ID、回执 ACK、刷新/路由恢复路径不重复业务写入；未知结果走原调用核对 |
| Web 入口 | 实际聊天挂载、追问/审批/取消交互正常；卸载与 owner 切换符合生命周期；快捷键不误触业务 |

普通协议与接线测试使用原项目的本地替身、临时数据库或测试服务，复用已有测试设施。真实业务行为在宿主测试环境使用虚构数据核验。读取返回字段不能证明未被覆盖的副作用；写操作后优先通过原系统的权威查询、回执或数据库测试断言核对。

只验收已经接入的路径，不强行添加宿主没有使用的浏览器桥或审批流程。若有写入未知、跨租户、异步作业等实际路径，分别增加对应案例。

## Agenstra 任务验收

后端能力任务复用 `agenstra-evaluate`。案例按 `docs/quick-integration.md` 和目标版本的 `EvaluationCase` 填写 `pack_id`、任务、预期状态、required/forbidden capabilities 与完整 Fact 字段断言。先用原始操作映射核对断言，再执行。

`AGENSTRA_SOURCE`、`HOST_ACCEPTANCE`、`HOST_REPORT` 是已选定的绝对路径，`AGENSTRA_TEST_SERVER` 是本次测试服务地址；用户 API key 由开发环境注入 `AGENSTRA_API_KEY`，不打印、不写入案例：

```sh
cd "$AGENSTRA_SOURCE"
go run ./cmd/agenstra-evaluate \
  --server "$AGENSTRA_TEST_SERVER" \
  --key-env AGENSTRA_API_KEY \
  --cases "$HOST_ACCEPTANCE" \
  --output "$HOST_REPORT"
```

该命令可能创建真实业务任务，应只针对已授权的测试主体、能力和数据运行；对已有任务使用案例 `run_id` 可只读复验。它使用用户运行权限，不能用管理员 key 代替。退出码 0 表示所给断言通过，1 表示案例失败，2 表示配置/命令错误。

工具从 `/runs` 检查状态、调用和被引用的完整 Fact，不自动审批、补充输入或核对未知操作；它不覆盖宿主登录路由、聊天组件与浏览器动作接线。纯浏览器或组合场景还要通过实际 Web 客户端和宿主测试验证对应操作，不能将后端 CLI 的结果代替 Web 验收。

需要用户处理审批或追问时保留原 run ID，处理后只读复验。创建结果未知时保留报告里的 request ID 和相同任务参数；查询证据、核对原任务后再恢复，不能换 ID 重发写任务。取消测试编排不证明上游业务已取消。

## 评判与交付

- 分别报告宿主构建/测试、协议接线和真实模型案例。固定模型证明协议路径，真实模型证明本次案例的理解与执行；缺少模型凭据时仍完成本地协议验证并标明真实模型未执行。
- 检查器应复用所选框架版本，关键成功条件保持与原业务需求一致。生成的测试需人工/代码审查或在受保护 CI 中核对，不允许修改断言、跳过失败用例或伪造业务查询来宣称通过。
- 检查实际 diff 与敏感文件，确认契约、类型声明、生成代码、真实 handler 和版本一致，排除凭据、测试数据库与无关变化。保留接入版本、操作映射、命令及测试输出。
- 失败按证据局部修复后重验受影响环节。缺少账号、凭据、运行环境或未授权的范围变更时仅暂停该部分，清楚记录未验证项目和解除阻塞所需的信息。
- 停止并确认本任务启动的服务/容器退出；对自建浏览器测试会话确认结束，对用户已有浏览器解除连接并保留原会话。

交付时用实际证据说明可用范围，禁止将一次通过推广为所有宿主或所有 coding agent 的可靠性结论。
