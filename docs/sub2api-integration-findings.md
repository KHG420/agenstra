# Sub2API 从零接入与任务质量验收

2026-10-03。本轮从框架 main `3724c88`、Sub2API `2f3fed2` 开始，两个项目都在独立工作树实施。框架原本地 main 已先快进同步；宿主原目录两个未提交的登录页修改和原有三个运行容器均保留。框架修复直接提交 main；宿主接入只保留在本地独立分支，不向宿主上游发布。

目标仍是：宿主声明和绑定已有业务能力、设置授权、选择模型与运行策略；框架负责可靠执行自然语言请求。本轮没有在框架核心添加 Sub2API 的业务流程或能力名分支。

## 接入工作

采用纯浏览器接入，复用宿主现有 Go/Gin 登录与 Vue/TypeScript API 函数：

| 宿主负责 | 实现 |
| --- | --- |
| 选择和声明已有能力 | frontend profile 声明 8 个动作：个人资料、用户分页/详情/更新、分组分页/详情/创建/更新 |
| 绑定原函数 | handler 调用原 `api/admin/users`、`api/admin/groups`、`api/user`；仅投影必要业务字段，密码和 API key 不进入结果 |
| 可信身份与授权 | Gin JWT 中间件验证当前用户；服务端按真实 ID/角色映射长期 Agent key，换短期票据。管理员、只读管理员和普通用户分别授权 |
| 确认写操作 | 所有写动作需要审批；审批绑定具体调用、参数哈希和修订版本 |
| 选择模型和运行策略 | 部署配置使用 deepseek-v4-flash / deepseek_chat，决策 thinking enabled、reasoning low，记忆 extraction thinking disabled；20 轮、40 工具调用、180 秒预算 |
| 装入界面 | 固定导出的 SDK、动作类型和版本文件，Vue 页面挂载正式聊天组件，配置同源代理及允许来源；页面观察只给路由和角色 |

框架负责对话上下文、查契约、工具引用、审批、异步浏览器回执、预算、暂停与恢复、诊断。宿主没有实现 Agent 决策循环、对话存储、提示词编排或自建聊天组件。必要的宿主手写接线约 200 行（票据/代理、handler、Vue 包装和导航/路由），另有业务 Schema、生成的 vendor 和实验脚本。

## 已修复的框架缺陷

**严格 TypeScript 宿主无法导入生成的版本文件。** `export-actions.mjs` 原来输出 `agenstra-profile.js`，缺少同名类型声明。宿主真实 `vue-tsc --noEmit` 报 TS7016。生成器现在同时输出 `agenstra-profile.d.ts`，保留准确的 handlerVersion 字面量，并随重新导出更新；不覆盖宿主业务实现。新增断言在修复前因 ENOENT 失败，修复后生成器测试和真实宿主类型检查通过。宿主无需关闭 strict 或手写声明。

**刷新后原任务后续调用一直 browser_offline。** Resume 会把会话 generation 从 1 改为 2，但 web_bindings 中任务仍为 1。页面心跳正常，后续上下文/业务调用却永久因代数不一致被拒绝。真实模型最后只报告已取得的用户数据，无法完成分组查询；这不是正确完成任务。

修复在同一个 SQLite 写事务中更新相同 owner、session、profile 的任务后续绑定，并将观察版本重置为 -1，要求重新读取页面上下文。旧命令保持原 generation 和回执：未开始的取消，已开始但无回执的仍为 unknown，不能重放。旧命令 begin 保持 generation fencing，旧原始回执仍可核对同一操作。测试覆盖刷新后新调用、重新观察、原成功命令不被迁移、其他标签不被修改，以及已有丢失 ACK/未知写入/版本漂移测试。修复前回归得到 browser_offline，修复后通过。

真实刷新案例修复前 7 次模型请求、任务质量失败；修复后 6 次请求，用户与分组查询均完成。单次成本差异不足以证明普遍性能提升，本次修复的结论是恢复正确执行。

## 真实模型与业务验收

使用独立 PostgreSQL/Redis、合成管理员和用户。初始数据是 11 个用户、3 个测试分组及原系统默认分组；合规状态用纯测试 fixture 准备，没有代用户调用条款接受接口。前半程业务 API 使用源码 revision 完全相同的隔离镜像，后续写操作、故障和界面验收使用接入工作树编译的真实后端。

最终记录 21 类场景。17 项终止为 completed（包括明确拒绝无权/不存在对象的回答），另有取消、追问和两项不确定写入暂停。对应业务与执行边界断言均符合预期。**这不是一次无失败的 21/21 连续跑测或生产成功率**：初期测试脚本遇到 queued run 尚未发布、审批状态名和 fixture ID 断言错误，已修正并保留原始记录；刷新失败作为框架缺陷保留修复前后证据。HTTP 500 和模拟响应丢失案例仍保留暂停状态，未计为业务任务成功。

| 场景 | 业务与回答证据 | 最终请求数 |
| --- | --- | ---: |
| 指定用户查询 | Alice ID=4、余额 12.5、并发 3 与后端一致 | 4 |
| 分页汇总 | 每页 2 条，完整读取 Page1–Page5，余额和为 15 | 6 |
| 状态/平台筛选 | 只返回活跃 openai 分组，排除停用/其他平台 | 4 |
| 跨步骤更新 | 先取得真实用户 ID，再把并发改成 7，读回确认 | 8 |
| 拒绝审批 | Alice 仍 active，没有禁用副作用 | 7 |
| 审批时取消 | 并发仍为 7，状态 cancelled | 5 |
| 创建并确认分组 | Lab-New 只创建一次，倍率 1.1 | 9 |
| 缺少字段 | needs_input，尚未创建 | 3 |
| 追问后续接 | 给出名称/平台/倍率后只创建一个 Lab-Clarified | 10 |
| 普通用户查询 | 只读取当前 member 账号，余额 8 | 4 |
| 普通用户/只读管理员越权请求 | 不调用写能力，原业务状态不变 | 3 / 4 |
| 多轮指代 | 第二轮正确指代 Alice 并重新读取；两个 run 的预算分别记录 | 见 JSON 两轮预算 |
| 相同消息 ID 重发 | 相同 run，更新只执行一次；同 ID 不同文本被拒绝 | 9 |
| 原回执响应丢失 | 重发原回执，更新 handler 只执行一次，最终读回正确 | 9 |
| 刷新恢复 | 原任务继续完成分组查询；旧命令不迁移 | 6 |
| 确定业务拒绝 | 非存在用户被拒绝，最终说明无法取得资料 | 5 |
| 宿主 500 拒绝管理员修改 | 实际账号保持 active，框架 needs_reconciliation | 5 |
| 写入成功后响应丢失 | 实际并发变为 10；只执行一次，框架暂停核对 | 5 |
| 真实 Vue 页面查询 | 经宿主 JWT、票据和 TS handler 查询两类实体，表格与后端一致 | 5 |
| 真实 Vue 页面审批 | 界面显示 ID=2、倍率=1.4；批准前后端为 1.2，批准后读回为 1.4 | 9 |

请求数包含记忆提取和格式恢复，不只计算决策轮数。简单用户查询的 4 次请求中，3 次是 decision、1 次是 memory_extraction；模型的 tokens、elapsed、用途、格式恢复和诊断保留在 [脱敏证据](evidence/sub2api-integration-2026-10-03.json)。隔离 owner 读取另一 owner 的 run 返回 404。没有以标准组件的“已完成”标签代替业务读回。

## 接入摩擦与保留限制

- 宿主没有固定 pnpm 版本：系统 pnpm 11.21.0 冻结安装报 overrides 不匹配，10.18.3 使用原锁文件成功。没有变更生产依赖或锁文件。Go 1.27 toolchain 成功下载并编译；框架使用自己的 Go 版本。
- Vite 的 `/agent` 前缀代理会同时命中 `/agent-assistant`，影响刷新。宿主改为 `^/agent/`，浏览器入口正确返回 SPA 页面；显式配置开发页面的允许 origin。它们是必要接线配置，不作为框架内核修复计数。
- 宿主禁用管理员的业务拒绝被包装成 HTTP 500 和通用 internal error，浏览器无法仅据此证明没有提交。框架正确暂停；接入方需要可信业务证据或明确的拒绝回执。不能把所有 500 都映射为确定失败。
- 静态部署仍需为每个认证身份设置可信 owner/key 映射与授权；新增身份需更新配置。Go 宿主仍需绑定票据路由和代理。本次没有增加账户自动同步层。
- 本轮选择 8 个管理业务能力；没有验收全部 Sub2API 管理接口、真实上游账号、支付/计费写操作、生产负载或模型统计性成功率。回答仍有模型差异；部分否定查询出现冗余核查，原始格式恢复及错误没有被删掉。

## 验证和收尾

框架 `make check` 通过：格式、diff、vet、golangci-lint、ESLint、Go race tests、95 项 Web 测试、命令构建。宿主 Agent 路由 race 测试、严格 Vue 类型检查、变更文件 ESLint 和完整前端 build 通过；宿主已有较大 chunk 的构建警告保留，没有顺手重构。

宿主 `agent/` 保存 profile、部署样例、接入说明、普通/故障验收和 lab 启停脚本。停止后已用 `lab.py start` 重新编译并启动最新框架、宿主和 Vite，确认 ready，再执行 stop/status 核对全部测试端口和容器已停止。固定导出的 SDK 虽被宿主默认的 vendor 忽略规则匹配，已逐文件纳入本地接入提交。凭据与完整运行状态位于权限受限的 ignored state，未进入 Git。只停止本轮记录的服务和三个测试容器，保留原有服务、原登录修改及浏览器原标签。
