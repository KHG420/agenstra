# Sub2API 第二轮真实任务评测

2026-10-03，在框架与 Sub2API 的独立工作树、专用本地服务及合成数据库中，继续通过宿主身份换票、同源代理和正式无 UI SDK 执行真实模型任务。基线是 `fc1c229`，模型为 `deepseek-v4-flash`，决策开启 thinking、推理强度 low，记忆提取关闭 thinking；预算为 20 个模型轮、40 次工具调用及 180 秒。这里的请求次数包含记忆提取、格式恢复和完成复核。

## 第一批结果与定位

| 场景 | 结果 | 模型请求 | 核对内容 |
| --- | --- | --- | --- |
| 会员读取自己资料 | 通过 | 4 | 身份、邮箱、余额与并发；业务 handler 仅访问自己的资料。 |
| 创建分组 → 修改刚创建的分组 → 读回 | 通过，3 条消息 | 21 | 实际创建 ID、一次创建及一次修改、平台、倍率、状态与后端值。 |
| 缺少创建参数后追问 | 失败 | 3 | 两次决策格式错误，未调用业务 handler。 |
| 修改分组时在审批处刷新 | 通过 | 10 | 保留会话、generation 只增加一次；写入 handler 仅执行一次。 |
| 审批前改口并丢失 steering 响应 | 通过 | 10 | 相同 request ID 重试；仅一条改口事件、零写入，业务值不变。 |

第一批共 7 次运行、48 个模型请求。之后单独重跑缺参数场景，再次失败，3 个模型请求。诊断的 `model_decision_schema_invalid` 不能说明具体错误，因此在本地增加临时诊断代理，仅将请求正文与响应保存到被忽略的私有目录，未保存或提交认证头。

实际模型连续两次返回 `input_schema: {"type":"string","enum":[…]}`。这是普通 JSON Schema 的合法组合，但框架的 `RequestedInputSchema` 是单字段文本输入契约：枚举要求 `type:"enum"`，`type:"string"` 禁止枚举。原有运行时提示只写了 string、enum、date 三个类型，没有提供其准确 JSON 形状；通用格式重试未补足信息，模型再次返回同一错误。

## 框架修复与验证

运行时现在明确给出 string、date、enum 的 JSON 形状，说明这是单个文本答案的契约，并给出可解析的枚举示例；组合答案可以省略 `input_schema`。修改位于运行时的决策补充提示，保留能力包提示及其持久指纹，未改变 HTTP、SDK 或持久化结构，也未放宽校验。

回归测试先返回实际观察到的 string+enum 错误响应，再从框架发给模型的提示中读取枚举示例，走正式 HTTP 模型适配器与 Runtime 格式恢复路径。测试在修复前失败，修复后进入 `needs_input`，同时保留非法答案拒绝和模型用量记录。上下文测试按当前运行时固定提示预留空间，仍检查实际总输入上限、历史裁剪、完整 Fact 引用及超限时不调用模型；记忆超限测试独立构造大提取源与可容纳的业务请求，避免依赖两段固定提示的长度差。

真实模型复测：较长的中间提示完成了两次追问及创建，10 个模型请求；最终压缩提示完成了组合追问及创建，8 个模型请求，实际后端平台为 gemini、倍率为 1.25。两个试验都保留了审批参数和成功回执。小样本说明已能完成触发任务，不能据此声称模型永远不会再产生非法决策，也不能把失败时的 3 次请求与完成任务的 8 次请求当作性能对比。

同一批中另一个刷新用例因测试脚本复用了刚创建的分组名而失败：后端拒绝重复创建，模型正确报告拒绝，最终断言找不到新创建对象。该结果归类为测试夹具问题，未计入框架修复成功；后续用例改用独立名称。

`make check` 通过：格式与空白检查、Go/JS 静态检查、Go 竞态测试、97 项 Web 测试以及命令构建。脱敏证据见 [第二轮证据](evidence/sub2api-stress-round2-2026-10-03.json)。证据保留失败及中间方案，私有模型请求正文、凭据及数据库未提交。
