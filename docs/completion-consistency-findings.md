# 动作成功但回答否认执行：定位与修复

2026-10-03，基于 main 的独立工作树完成。框架修改不涉及抽奖宿主业务规则、主工作目录或真实人员数据。

## 可核对的执行事实

隔离接入验收的运行 `5b23fe8c-cd7c-5486-820c-d39c8fcf1dd0` 使用 156 位虚构参与者。用户要求“开始一轮三等奖，先让我确认再执行”。运行审计有 `approval_requested`、`approval_granted`；开始操作的 invocation 为 `81692c56-c530-548f-93f0-e9cfecd1c418`，确定回执为 `succeeded`，异步操作终态同样为 `succeeded`。

执行前，Fact `c1551298-822e-45db-8d71-4fcb90b82b60` 的 revision 为 0，`active_round` 为 null。执行后，Fact `05269c82-0d71-4e32-8440-30c749d48182` 的 revision 为 1，包含本次创建的三等奖轮次，人数为 3，未揭晓、历史中奖记录为 0。

模型最后却写“已有一个进行中的三等奖轮次，因此无法再发起新的三等奖轮次”，并要求用户在揭晓和取消之间确认。它引用了上述两个真实 Fact，业务对象引用也解析到真实轮次 ID，因此原有引用检查通过。

原验收只存有决策、观察、完整 Fact、回执及请求参数/耗时统计，没有保存这个运行每次实际 HTTP 模型请求的完整正文。本次复核重建了相关上下文；不能据此断言模型内部推理的唯一原因。回放样本保存在 `testdata/completion-start-round.json`，包含相关合成业务快照、观察、确定回执和当时的错误草稿。

## 框架层缺口

1. 普通状态快照没有充分表达因果关系。执行后的“对象存在”是本次成功操作的结果，模型却把它当成执行前的限制。Fact 值正确，叙述的时间和动作归因错误。
2. 审批通过发生在宿主执行流程中，模型缺少明确的信息来解释“先确认再执行”已满足。首次真实模型复核虽然承认开始成功，其中一次仍暗示可能没有先确认；这促使本次补充能力的审批要求及宿主强制审批规则。
3. `final` 原来只检查 Fact 引用、业务对象路径，以及可选的宿主完成校验。引用合法不会证明整段叙述正确；宿主没有额外自然语言校验时，矛盾直接成为已完成回答。
4. 标准聊天组件没有直接显示确定的写回执，用户主要依赖模型文字和任务状态。回答生成失败时，通用“重试”提示还可能诱发重复提交已成功动作。

## 本次实现

`action_outcomes` 以 invocation 关联每次写操作、当前终态和结果 Fact，优先采用实际回执，并使用当前待执行项的更新回执；临时运行、拒绝批准和既有检查点可从完整观察重建。异步结果指向同一次动作的终态 poll Fact。投影不会改写审计状态，不向模型暴露私有作业 ID、结果哈希或隐藏业务字段；预算裁剪保留这份执行依据。

最终草稿包含写操作结果时，在现有决策调用流程中增加一次回答复核。复核依据原请求、补充输入、动作结果及可见 Fact 纠正执行叙述，输出同一个 `final` 契约；其他决策种类被拒绝，业务工具不会执行。草稿先保留到审计，未经复核不写入对用户的 `answer_markdown`。复核结果继续经过现有引用和业务完成检查。格式纠正、轮次和 Token 限制、模型请求预留、检查点、固定模型配置和用量统计均沿用既有机制。

正常写任务增加一次请求，只读、计算和对话任务不增加。复核调用标记为 `completion_review`，管理界面可单独查看成本。复核失败或预算耗尽时不发布草稿，确定业务回执仍保留。标准聊天组件在回答旁显示成功、仅受理、失败或未知回执，并区分任务未完成与业务动作结果。

本次没有更改宿主业务接口、决策输出格式、数据库结构、生产依赖或能力包指纹。新增内容是模型上下文的可选字段，以及遥测用途值；自定义模型适配器应支持写任务最终回答后的额外 `Decide` 请求。复核使用已固定的决策模型，不新增模型选择配置。

## 验证与成本

先构造“操作前无对象 → 本次创建成功 → 操作后对象存在 → 错误否认创建”的最小测试，旧实现确实将错误草稿直接标记 completed。修复后，该草稿只进入审计，复核回答才可发布。

回归覆盖批准后的同步写、异步终态 poll、仅受理、作业失败、批准拒绝、结果未知、多次尝试、隐藏作业字段、上下文裁剪、复核违规调用工具、模型故障、轮次/Token/上下文耗尽、检查点失败、宿主完成校验和业务对象引用。全部 Go 竞态测试、vet 和命令构建通过；Web 的 71 个测试通过。

最终版本对同一历史错误草稿做了三次真实模型回放，逐段人工核对：全部明确承认批准后本次已经开始三等奖轮次，正确保留人数 3、未揭晓和没有中奖名单。模型没有调用业务工具。每次只有一笔真实网关复核请求；注入的草稿不访问模型网关。
