# Sub2API 真实接入与 72 小时运行验证

状态：**进行中，第 4 波六身份复验通过，持续监督已恢复**。本轮从此前接入审查中“真实业务接入和长期运行尚未证明”的缺口出发。目标是在隔离 Sub2API 实验环境中，让六个不同身份持续经宿主 JWT、Agenstra 短期票据、正式 Web SDK 和真实业务 API 使用框架，并核对执行、权限、资源增长和备份。负载使用六个独立 SDK 客户端并发执行，尚不等于六个真实浏览器的人工作业验收。本文只记录已取得的脱敏结论与后续验收口径；凭据、完整运行账本、业务回执和进程归属留在权限受限的私有实验状态中。

## 范围与费用约束

六个新建实验身份分别为两名全权限管理员、两名只读管理员、两名普通会员。各身份有独立账号、框架 owner、客户端会话和自然语言任务；写操作限定在新建的专用测试账号或分组，审批须核对能力、真实目标、参数、哈希与版本，再按业务 API 读回。普通会员只能读取本人资料，只读管理员不得执行写能力。重复 client ID、拒绝审批、跨 owner 的 run、events、真实 Fact 读取也纳入验收。

模型经原有 Sub2API 网关的 `hy3` 免费通道接入隔离实验，而非直接使用原业务服务的数据或容器。用户给出的总费用上限为人民币 **50 元**；本地预算代理采用更保守的 40 元限额与单请求预留。截至上海时间 2026-10-04 01:40，代理和网关计费记录共核对 68 次已结算模型请求、网关账面费用 0 元、未结算预留 0 元；其中首轮 29 次、六身份复验 39 次。免费依据来自用户对现有通道的说明及专用网关分组的零价配置；没有充值或支付。本地账本和网关零价配置不证明上游供应商真实账单为零。预算、通道或结算无法确认时，停止新增任务，不自动重置账本。

## 首轮结果与保留的问题

首次六身份并发 smoke 有 **3/6** 通过，不能作为持续正常运行的成功起点。两名普通会员和一名只读管理员的任务完成；另三项保留原始失败证据：一名管理员的 run 超过当时脚本 220 秒等待期限后被取消，一名管理员的写审批被测试脚本误判，一名只读管理员在真实 handler 已返回后进入 `needs_reconciliation`。后者已保存的命令回执为成功，但下一次 Host 推进被整批慢任务延迟到 operation deadline，期间没有状态查询；原路径直接进入未知。修复后使用既有浏览器核对接口结算原命令，日志确认其 invocation 为 `succeeded` 且已核对，不重放 handler。原 run 随后因原有总时限已超出而保持失败，不能把业务回执成功写成该 run 成功。

审批误判已定位：模型在专用账号并发更新参数中附带原值不变的 `status`，旧脚本只允许 `id` 和 `concurrency` 两个键。脚本现于审批和 handler 执行前各自读取当前业务状态，要求附带状态与真实原值一致，实际 `PUT` 仍只发送目标并发字段，并记录最终状态保持不变。排队消息的 run 尚未发布时，驱动轮询同一消息与 run，不用新请求重发。脚本单 run 等待默认调整为 600 秒，可在 30–900 秒范围内显式设置；实验运行上限为 900 秒、并发上限为六、模型单请求超时为 120 秒。以上修正仅消除已证明的实验误报，**首轮 3/6 记录未被改写**。

修复后在上海时间 2026-10-04 01:35:36 完成第二次 smoke，**6/6 通过**，三个跨 owner 资源隔离断言均通过。本人实际读取的 Fact 存在，另一身份对同一 run、events、Fact 均得到 404。管理员重复发送相同 client ID 得到同一 run ID；批准的专用账号更新 handler 只执行一次，业务读回值正确且状态不变；拒绝审批的更新未进入 handler。

## 本轮框架修复与验证边界

同步运行 worker 先前可被一个慢模型调用占住，使另一个已受理作业的到期状态查询延迟。服务端改为有界并发驱动不同 run，保留 Host 的全局槽位、SQLite claim/租约 fencing，并在关闭时取消和等待已启动 worker。定向测试覆盖“一个模型等待时独立作业仍可查询”与关闭时全部 worker 退出；这证明该触发条件，尚不代表 72 小时吞吐已达标。

已受理作业达到 operation deadline 时，原路径会直接进入结果未知，可能错过恰好已完成的可信状态。修复在启用超时核对、授权与预算允许时先进行一次绑定原作业身份的最终只读查询；成功、失败、仍在进行、查询不可用分别保留其证据。若 poll 预算已耗尽，不能把已受理但尚未确认终态的作业说成业务失败；预算与授权不足时保留未知或暂停授权，不重放原写操作。回归覆盖终态、错误作业 ID、未知结果、权限撤销、预算与重启后的原轮询身份。

核对旧命令时还发现成功 invocation 残留此前的未知错误码：成功观察与回执采集没有清除旧错误。新增回归先证明旧实现失败，再让确认成功的 observation 和 receipt 清除此前错误；历史审计事件保持原样，不回写改造旧实验记录。

真实跨 owner 检查还暴露 Web SDK 的解析缺陷：框架可返回 HTTP 404 纯文本，旧客户端先执行 JSON 解析而抛 `SyntaxError`，丢失状态与安全错误码。SDK 现对非 2xx 的空、纯文本或无效 JSON 响应按 HTTP 状态给出安全 `AgenstraError`；结构化 JSON 错误保持原语义，只有明确的 JSON `unauthorized` 才换票重试，2xx 无效 JSON 仍保留原解析失败语义。客户端 38 项测试和 Web lint 已通过。隔离验收使用来源身份实际可读取的 Fact，再核对另一个身份对 run、events、该 Fact 均得到 404；不会用不存在的产物 ID 冒充授权证据。

## 持续阶段验收规则

只有修复后的手动六身份 smoke 达到 **6/6**、真实 Fact 隔离通过、业务读回与费用/通道核对通过，才启用持久监督。监督器以预算代理保存的 `started_at` 和 `deadline_at` 为 72 小时时间轴，每小时发起一波六身份任务，每身份同一波至多一个 run；每 60 秒采样框架 `/healthz` 与 `/readyz`、宿主健康、代理状态、实验进程 RSS/CPU/FD、两份 SQLite 主文件及 WAL/SHM 大小和可用磁盘。结果逐条追加，失败、采样缺口和响应超期均保留，不能将未采样时段记作连续正常运行。

每六小时在无波次运行的间隙对两份 SQLite 库分别执行 online backup，逐库核对完整性、全表行数和逻辑哈希；保留各自快照时间与旧备份。顺序取得的两个快照**不是跨库一致事务**，逐库可读也不证明完整恢复成功。完整恢复还需用隔离副本执行并验收。每十二小时刷新原网关管理员 JWT 时只读取原容器配置并登录，不改动原容器。模型账面未知、费用上限风险、写回执未知、波次失败或中断均停止新增波次；在人工核对原 run、回执、业务状态和预算前不重发写操作。到代理 72 小时截止时停止新负载，按记录的 PID、启动时间、命令和容器 ID 清理本任务资源，保留用户原有网关容器和浏览器。

真实脱敏响应观测修正了单次最小探针的推断：即使传入 `thinking=disabled`，六次 512 输出记忆请求仍各报告 512 reasoning tokens，没有 content；实际不能据此认定该通道已关闭思考。记忆输出额度提高到同通道已允许的 4096，单次定向提取验证返回 HTTP 200、有效契约及一条符合合成文本的偏好提议，605 completion tokens 中仍有 561 reasoning tokens。没有执行或信任思考文本，框架仍只解析结构化内容。首次脚本预算类型预检查失败发生在 POST 之前，修正后独占标记只允许一次模型请求。截至恢复监督时，累计 **181 次已结算、0 次未知、0 元网关费用、0 元未结算预留**；这些数值仍不替代上游独立账单。
